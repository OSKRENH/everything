# Полезные идеи из устаревшей ветки Claude

Источник аудита: бывшая ветка `claude/recipe-suggestion-app-dnkzxf`, которая была основана на самом первом коммите репозитория (`07fcd581e39541fdd0479ada5b00c5cdb70dfe38`) и разошлась с актуальным приложением. Старую React/Pages-архитектуру переносить в `main` нельзя.

Последний сохранённый снимок старой реализации до очистки веток: `5ed36847171785a94245813b30600e3dab8e8dd6`.

## Что стоит перенести в актуальный Кутно

1. **Список покупок**
   - добавление недостающего продукта из карточки/рецепта одним действием;
   - отдельный список покупок;
   - действие «куплено» с переносом продукта в кухню;
   - гостевой localStorage + синхронизация с аккаунтом.

2. **Количество продуктов**
   - необязательное количество у продукта на кухне;
   - количество у позиции в списке покупок;
   - показывать известное количество недостающего ингредиента в рецепте.
   - В актуальной архитектуре хранить количества отдельно от массива имён продуктов, чтобы не ломать matching engine.

3. **Фильтр «можно готовить сейчас» и сортировка по недостающим**
   - идея полезная, но в актуальном Кутно уже есть readiness/missing-логика;
   - переносить только недостающий UX-контрол, не старый matcher.

4. **Защита API**
   - rate limit на неудачные попытки авторизации/регистрации применим только там, где соответствующие эндпоинты реально существуют в текущей архитектуре;
   - не переносить старую username/password auth вслепую;
   - rate limit публичных рецептов проверять отдельно, чтобы не ухудшить SEO и обычный просмотр.

## Что уже есть в актуальном Кутно и переносить не нужно

- избранное и его синхронизация с аккаунтом;
- поиск/фильтры каталога;
- текущая логика совпадений и недостающих ингредиентов;
- современный интерфейс и навигация;
- текущий Worker/Vite runtime и публичные SEO-маршруты.

## Запрещённый путь миграции

Не копировать в `main` старые каталоги `client/`, `functions/` или старую React-навигацию. Полезные функции должны быть реализованы заново поверх текущих `src/`, `worker/`, `public/recipe-data` и текущего состояния/feature-state API.
